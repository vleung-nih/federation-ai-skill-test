    The `/subject` endpoint is a metadata endpoint for listing subject records known by a CCDI Federation server.

`GET /api/v1/subject`

It returns paginated subject-level metadata, not raw research data. Each returned subject can include:

- `id`: primary subject identifier
- `kind`: subject type, such as `Participant`, `Patient Derived Xenograft`, `Cell Line`, or `Organoid`
- `metadata`: harmonized subject metadata
- `gateways`: access/request information, when available
- top-level response `summary.counts.current` and `summary.counts.all`
- `data`: the page of subject records
- optional top-level `gateways`: reusable named gateway objects

**Supported Filters**

Filters are query parameters. Matching is exact and case-sensitive.

Documented harmonized filters include:

- `sex`
- `race`
- `ethnicity`
- `identifiers`
- `vital_status`
- `age_at_vital_status`
- `depositions`

Filtering behavior:

- Single-value fields match only when the field exactly equals the query string.
- Multi-value fields match if any value exactly equals the query string.
- Null or empty fields do not match.
- Multiple filters are combined with logical AND.
- The endpoint does not natively support OR across different fields; for that, run separate queries and union the results client-side.

Unharmonized fields are intended to be filterable using a `metadata.unharmonized.<field>`-style path, but the OpenAPI notes that the literal Swagger placeholder `metadata.unharmonized.<field>` is symbolic, not a real parameter name to submit as-is.

**Pagination**

Pagination uses:

- `page`: page number to retrieve. The docs describe this as 1-based and defaulting to `1`.
- `per_page`: number of records per page. Each server may choose its own default; the community convention is `100` when reasonable.

The response includes paging information in two places:

- Body: `summary.counts.current` is the number of records on the current page, and `summary.counts.all` is the total across all pages.
- HTTP `Link` header: includes pagination URLs with relations such as `first`, `last`, and optionally `next` and `prev`.

A typical request shape is:

```http
GET /api/v1/subject?sex=Female&page=1&per_page=100
```

Possible documented errors include `404` when line-level subject metadata cannot be shared by a server, and `422` for invalid query or pagination parameters. No live data was fetched.
